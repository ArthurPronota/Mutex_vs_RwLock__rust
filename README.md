# Пояснение кода: `Mutex` vs `RwLock`

## Что демонстрирует код

Пример показывает **два** способа защиты общего изменяемого состояния между потоками:

1. **`Arc<RwLock<i32>>`** — блокировка чтения-записи.
2. **`Arc<Mutex<i32>>`** — эксклюзивная блокировка.

Оба используют `Arc` для **разделяемого владения**.

## Часть 1: `Arc<RwLock<i32>>`

```rust
let v = Arc::new(RwLock::new(10));

let my_hand = thread::spawn({
    let v_clone = v.clone();
    move || {
        match v_clone.write() {
            Ok(mut r) => {
                *r += 10;
                Ok(*r)
            },
            Err(err) => Err(format!("{}", err)),
        }
    }
});
```

### Что происходит

1. **`RwLock::new(10)`** — создаёт `RwLock<i32>` со значением 10.
2. **`Arc::new(...)`** — оборачивает в `Arc` для **разделяемого** владения.
3. **`v.clone()`** — клон `Arc` (**увеличивает** счётчик).
4. **`v_clone.write()`** — захватывает **эксклюзивную** блокировку для **записи**.
5. **`*r += 10`** — изменяет значение (10 → 20).
6. **`Ok(*r)`** — возвращает новое значение (20).
7. **`Err(err)`** — если блокировка **отравлена** (poisoned).

### Что такое **отравление** (`poisoned`)

Если поток **паникует**, пока **держит** блокировку, `RwLock`/`Mutex` становится **отравленным**:

```rust
Err(PoisonError { .. })
```

Последующие `lock()`/`read()`/`write()` вернут `Err`. Это защита от **несогласованного** состояния.

### Обработка в `main`

```rust
match my_hand.join() {
    Ok(res) => match res {
        Ok(r) => println!("result: {}", r),   // 20
        Err(err) => eprintln!("Error: {}", err),
    },
    Err(err) => println!("thread error: {:?}", err),
}
```

- **`my_hand.join()`** — возвращает `Result`:
  - `Ok(res)` — поток **завершился**;
  - `Err(err)` — поток **паниковал**.
- **`res`** — результат замыкания (`Result<i32, String>`).
- **`Ok(r)`** — успех → печатаем `20`.

### Чтение после записи

```rust
println!("Readed data: {}", *v.read().unwrap());   // 20
```

- **`v.read()`** — захватывает **разделяемую** блокировку.
- **`*...`** — разыменование.
- **`unwrap()`** — паника, если `RwLock` отравлен.

## Часть 2: `Arc<Mutex<i32>>`

```rust
let m = Arc::new(Mutex::new(30));

let my_hand_2 = thread::spawn({
    let m_clone = m.clone();
    move || {
        match m_clone.lock() {
            Ok(mut res) => {
                *res += 20;
                Ok(*res)
            },
            Err(err) => Err(format!("{}", err)),
        }
    }
});
```

### Что происходит

1. **`Mutex::new(30)`** — создаёт `Mutex<i32>` со значением 30.
2. **`Arc::new(...)`** — оборачивает в `Arc`.
3. **`m_clone.lock()`** — захватывает **эксклюзивную** блокировку.
4. **`*res += 20`** — изменяет значение (30 → 50).
5. **`Ok(*res)`** — возвращает новое значение (50).

### Обработка

Аналогично `RwLock`:

```rust
match my_hand_2.join() {
    Ok(res) => match res {
        Ok(r) => println!("result: {r}"),   // 50
        Err(err) => eprintln!("Error: {err}"),
    },
    Err(err) => eprintln!("thread error: {err:?}"),
}
```

## Ключевое различие: `Mutex` vs `RwLock`

### `Mutex` — эксклюзивный доступ

```rust
let m = Mutex::new(30);

let guard = m.lock().unwrap();   // ← только ОДИН поток
*guard += 20;
// guard дропается → блокировка освобождается
```

- **Один поток** владеет данными.
- **Все** остальные **ждут**.
- **Простой** и **предсказуемый**.

### `RwLock` — чтение-запись

```rust
let v = RwLock::new(10);

// Много читателей одновременно
let r1 = v.read().unwrap();
let r2 = v.read().unwrap();
// ✅ параллельно

// Но писатель — только один
let mut w = v.write().unwrap();
*w += 10;
// w дропается → блокировка освобождается
```

- **Много читателей** одновременно.
- **Один писатель** — блокирует всех.
- **Сложнее** и **дороже**.

## Сравнительная таблица

| | `Mutex` | `RwLock` |
|---|---|---|
| **Читатели** | 1 | **Много** |
| **Писатели** | 1 | 1 |
| **Одновременный доступ** | Только 1 поток | Много читателей **ИЛИ** 1 писатель |
| **Стоимость входа** | Дёшево | **Дороже** |
| **Стоимость выхода** | Дёшево | **Дороже** |
| **Простой** | ✅ | ⚠️ Сложнее |
| **Starvation** | ❌ | ⚠️ Возможен |
| **`read()`/`write()`** | Нет | ✅ |
| **`lock()`** | ✅ | Нет |

## Когда выбирать `Mutex`

**По умолчанию** — `Mutex`:

- **Короткие** критические секции.
- **Нет** явного перевеса читателей.
- **Простота** важнее.
- **Не знаете**, что выбрать.

## Когда выбирать `RwLock`

**Только** если:

- **Читатели** держат блокировку **долго**.
- **Писатели** — **редки**.
- **Профилирование** показало, что `RwLock` **быстрее**.
- Вы **понимаете** проблему **starvation**.

### Проблема starvation в `RwLock`

Если **читатели** постоянно захватывают `read()`, **писатель** может **никогда** не получить `write()`. Это **starvation** (голод).

**Решение:** некоторые реализации `RwLock` дают **приоритет писателям**. Но это может привести к **голоду читателей**.

## Практический совет

> «Если не уверены, начинайте с `Mutex`. Меняйте на `RwLock` только после **измерения** и с учётом **приоритета писателей**, иначе можно получить **starvation**.»

## Полный рабочий пример

```rust
use std::sync::{Arc, Mutex, RwLock};
use std::thread;

fn main() {
    // === RwLock ===
    let v = Arc::new(RwLock::new(10));

    let my_hand = thread::spawn({
        let v_clone = v.clone();
        move || {
            match v_clone.write() {
                Ok(mut r) => {
                    *r += 10;
                    Ok(*r)
                },
                Err(err) => Err(format!("{}", err)),
            }
        }
    });

    match my_hand.join() {
        Ok(Ok(r)) => println!("RwLock result: {}", r),        // 20
        Ok(Err(err)) => eprintln!("RwLock error: {}", err),
        Err(err) => eprintln!("thread error: {:?}", err),
    }

    println!("Read: {}", *v.read().unwrap());                  // 20

    // === Mutex ===
    let m = Arc::new(Mutex::new(30));

    let my_hand_2 = thread::spawn({
        let m_clone = m.clone();
        move || {
            match m_clone.lock() {
                Ok(mut res) => {
                    *res += 20;
                    Ok(*res)
                },
                Err(err) => Err(format!("{}", err)),
            }
        }
    });

    match my_hand_2.join() {
        Ok(Ok(r)) => println!("Mutex result: {}", r),          // 50
        Ok(Err(err)) => eprintln!("Mutex error: {}", err),
        Err(err) => eprintln!("thread error: {:?}", err),
    }
}
```

**Вывод:**

```
RwLock result: 20
Read: 20
Mutex result: 50
```

## Сводная таблица

| Аспект | `Mutex` | `RwLock` |
|---|---|---|
| **Модель** | Эксклюзивная | Читатели/писатели |
| **Читателей одновременно** | 1 | Много |
| **Писателей одновременно** | 1 | 1 |
| **Методы** | `lock()` | `read()`, `write()` |
| **Стоимость** | Дешевле | Дороже |
| **Starvation** | Нет | Возможен |
| **Когда использовать** | По умолчанию | Долгие чтения, редкие записи |
| **Отравление** | `PoisonError` | `PoisonError` |

## Итог

- **`Mutex`** — **эксклюзивный** доступ, **один** поток.
- **`RwLock`** — **много читателей** ИЛИ **один писатель**.
- **`RwLock` дороже** на вход/выход.
- **`Mutex`** — **по умолчанию** для коротких секций.
- **`RwLock`** — когда **читатели долго** держат блокировку, а **писатели редки**.
- **Starvation** — риск в `RwLock` при большом числе читателей.
- **Профилируйте**, прежде чем менять `Mutex` на `RwLock`.
- **Правило:** «Не уверены — начинайте с `Mutex`.»
